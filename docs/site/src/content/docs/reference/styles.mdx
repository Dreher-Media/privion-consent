Opt-in. Components stay headless if you skip the import.

The stylesheet targets **both** attribute conventions used across the bindings — unprefixed `[privion-banner]` (DOM adapter, Astro components) and prefixed `[data-privion-banner]` (React components) — so a single import covers any binding.

## Theme tokens

Every visual decision is exposed as a CSS custom property. Override them at `:root` (or any narrower scope) without touching the stylesheet itself.

| Property                   | Default (light)                     | Notes                                                                   |
| -------------------------- | ----------------------------------- | ----------------------------------------------------------------------- |
| `--privion-bg`             | `#ffffff`                           | Banner / panel background                                               |
| `--privion-fg`             | `#16181d`                           | Body text                                                               |
| `--privion-muted`          | `#5b616e`                           | Secondary text (descriptions, badges)                                   |
| `--privion-border`         | `#e4e6eb`                           | Hairlines between toggle rows, secondary button outline                 |
| `--privion-accent`         | `#16181d`                           | Accept all, Reject all, Save preferences, switch "on" track             |
| `--privion-accent-fg`      | `#ffffff`                           | Text on those buttons, switch thumb when on                             |
| `--privion-radius`         | `0.875rem`                          | Banner / panel corner radius                                            |
| `--privion-shadow`         | layered soft shadow                 | Banner / panel elevation                                                |
| `--privion-font`           | `inherit`                           | Font family; inherits the page font so the UI reads as part of the site |
| `--privion-z-banner`       | `1000`                              | Banner `z-index`                                                        |
| `--privion-z-preferences`  | `1001`                              | Preferences modal `z-index`                                             |
| `--privion-backdrop`       | `rgb(16 18 24 / 45%)`               | Preferences modal backdrop                                              |
| `--privion-control-radius` | _unset_ → `0.55 × --privion-radius` | Button radius. Set `--privion-radius: 0` and buttons go square too      |
| `--privion-focus`          | _unset_ → accent at 55 %            | Focus ring                                                              |
| `--privion-switch-on`      | _unset_ → `--privion-accent`        | Switch track when on                                                    |
| `--privion-switch-off`     | _unset_ → fg at 22 % over bg        | Switch track when off                                                   |

The four optional tokens are resolved where they are used, so overriding a base token in a narrower scope (see below) carries through to them.

## Dark mode

Two routes:

<TabItem label="Force a theme">

```html
<html data-privion-theme="dark">
  ...
</html>
<html data-privion-theme="light">
  ...
</html>
```

Useful for theme-toggle UIs where users override the system preference inside your app.

## Customizing

### A few tweaks

Redefine specific tokens on `:root`:

```css
:root {
  --privion-accent: #7c3aed;
  --privion-accent-fg: #ffffff;
  --privion-radius: 0;
}
```

### Scoped overrides

For pages or sections where you want a different look:

```css
.brand-section {
  --privion-accent: #ec4899;
  --privion-radius: 1.5rem;
}
```

Any banner / preferences rendered inside `.brand-section` picks up the override.

### Fully custom CSS

Skip the import entirely and target the attribute selectors:

```css
[privion-banner],
[data-privion-banner] {
  position: fixed;
  bottom: 1rem;
  /* your design */
}
```

The DOM adapter takes care of show/hide via the `hidden` attribute. Your CSS doesn't need to know about consent state — just target the elements.

### Mixing with the bundled stylesheet

Import the bundled stylesheet, then add overriding rules:

```css
@import '@privion-consent/dom/styles.css';

/* Stretch banner to full viewport width */
[privion-banner],
[data-privion-banner] {
  inset: auto 0 0 0;
  max-width: none;
  border-radius: 0;
}
```

## Layout details

### Structural hooks

The bundled Astro and React components emit a few attributes that exist only as layout hooks for the stylesheet. They carry no behavior. Hand-written markup without them still renders sensibly (the banner falls back to one wrapping row, toggles to plain rows), but using them gets you the full layout:

```html
<div privion-banner hidden role="region" aria-label="Cookie consent">
  <div privion-banner-body><p>…</p></div>
  <div privion-banner-actions>
    <button type="button" privion-open-preferences>Customize</button>
    <button type="button" privion-reject-all>Reject all</button>
    <button type="button" privion-accept-all>Accept all</button>
  </div>
</div>

<div privion-preferences hidden>
  <div privion-preferences-panel role="dialog" aria-modal="true" aria-labelledby="pp-title">
    <div privion-preferences-header>
      <h2 id="pp-title">Privacy preferences</h2>
      <button type="button" privion-close-preferences aria-label="Close">…</button>
    </div>
    <p privion-preferences-intro>…</p>
    <div privion-preferences-categories>
      <label privion-category>
        <span privion-category-text>
          <span privion-category-label>Analytics</span>
          <span privion-category-description>…</span>
        </span>
        <input type="checkbox" role="switch" privion-toggle="analytics" />
      </label>
    </div>
    <div privion-preferences-footer>
      <button type="button" privion-save-preferences>Save preferences</button>
    </div>
  </div>
</div>
```

React emits the same hooks with a `data-` prefix.

### Banner

A floating card, centred at the bottom, up to `44rem` wide. The copy takes the first row; underneath, Customize sits on the start side and Reject all / Accept all on the end side. Below `34rem` viewport width the card docks closer to the edges and the buttons go full width: Reject all and Accept all side by side, Customize underneath.

### Preferences modal

A centred card up to `30rem` wide over a dimmed backdrop, with a header (title and close button), an optional intro, a scrollable list of category rows and a footer with the save button. On small screens it docks to the bottom edge. The panel never exceeds the viewport height; the category list scrolls instead.

The DOM adapter closes it on the close button (`[privion-close-preferences]`), on Escape and on a click on the backdrop. Closing discards unsaved toggle changes. Opening moves focus to the first switch; closing returns focus to the element that opened it.

### Buttons and switches

Reject all and Accept all carry **equal visual weight**. Supervisory authorities (DSK, CNIL, EDPB) expect rejecting to be as easy and as visible as accepting, so the default skin does not demote "Reject all" to a ghost button. Save preferences shares that style; Customize and other buttons are outlined.

Every checkbox inside the preferences renders as a switch. The native input stays in place, so keyboard use and form semantics are unchanged.

## Accessibility

- The bundled banner is a `role="region"` landmark with an accessible name; the preferences panel is `role="dialog"` with `aria-modal` and a labelled title. Add the same to hand-written markup.
- Focus moves into the dialog on open and back to the trigger on close; Escape closes it. Focus is not trapped; if you need a hard trap, wrap your own `<dialog>`.
- Buttons are at least 44px tall, and every control shows a visible `:focus-visible` ring.
- `prefers-reduced-motion` turns off the entrance animations and switch transitions.
- Color contrast: the default text, muted text and button colors clear WCAG AA in both themes.
